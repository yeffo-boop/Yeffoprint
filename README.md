# YeffoPrint

Custom WordPress + WooCommerce e-commerce experience for YeffoPrint — a premium custom printing brand.

- [`docs/PROJECT_SPEC.md`](docs/PROJECT_SPEC.md) — what to build
- [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md) — how it's structured, and the log of implementation decisions

## Codebases

| Path | Responsibility |
|---|---|
| `yeffoprint/` | Block theme — visual presentation only |
| `yeffoprint-core/` | Plugin — business logic, data model, pricing, orders |

Business-critical functionality lives in `yeffoprint-core` and must never depend on the active theme.

## Status

- **Phase 1 (Foundation)** — done: repo scaffolding, `theme.json` design tokens, and the core data-record post types (Templates, Materials, Sizes, Pricing Rules, Custom Orders, Proofs).
- **Phase 2 (Global UI)** — done: floating glass header with announcement bar, search/cart drawers, footer, button/card/form styles, and accessibility foundations (focus-visible, reduced-motion, skip link, drawer focus trapping).
- **Phase 3 (Storefront)** — done: homepage (assembled from block patterns — trimmed post-launch to Hero/Featured Designs/How It Works/Fully Custom CTA/Materials, see `docs/ARCHITECTURE.md` §9), the Shop Labels gallery (`/shop-labels/`) with server-rendered Style/Color/Material filters and Featured/Newest/Most Popular sort, the gallery card as a theme-owned dynamic block, and predictive search (extends core search to match style/color/material tags, not just title).
- **Phase 4 (Template Management)** — done: a nondeveloper can now add a Template entirely from wp-admin — featured/badge/popularity, vial mockup image (media library picker), compatible Sizes/Materials, and a full customization-field-schema repeater (add/remove/reorder fields with type, default, required, max chars, position, alignment, font sizing, formatting rule, preview behavior, admin description). Materials and Sizes also got real admin CRUD (pricing, print dimensions, drag-orderable sort, active/inactive via Publish/Draft).
- **Phase 5 (Configurator)** — done: the live Label Configurator at each Template's page (`/shop-labels/{template}/`) — synced Label View/Vial View preview, Size/Material selectors, dynamically-rendered customization fields with live character counters, auto-scaling preview text with a clear overflow warning when a field genuinely doesn't fit, quantity shortcuts, and a full multi-variant batch editor (add/switch/duplicate/remove labels within one order, each with its own field values and quantity). Backed by a new public read-only REST endpoint that hands the configurator everything it needs in one call. Add to Cart is a working stub (Phase 7 wires it to WooCommerce).
- **Phase 6 (Pricing)** — done: a real Pricing Rule admin screen (base price, $25 custom design fee, a keyboard-operable bulk-discount-tier repeater) backs `(base + adjustments − discounts) × quantity` exactly as specified. The configurator now shows an instant client-side estimate, then swaps in the authoritative, discount-aware breakdown (base/material/size/quantity/discount/total, each shown separately) from a new public `/pricing/calculate` endpoint — the same server-validated number a future Add to Cart would submit, never a client-trusted total.
- **Phase 7 (WooCommerce Commerce Integration)** — done: Add to Cart is fully wired up. Each Template gets one hidden, made-to-order WooCommerce product (never a template×size×material variation explosion); Add to Cart server-validates the whole batch, adds it as one cart line item, and opens the branded slide-out cart drawer (thumbnail, size, material, quantity, live price, Edit customization, Checkout/View Cart) that's been waiting since Phase 2. Cart price is always live-recalculated; placing an order freezes a full structured snapshot (template, size, material, pricing, and each variant) onto the order line item. `wp yeffoprint setup-shipping` configures the spec's flat-rate shipping zones (USPS $6 / UPS $15 / International $25). Size/Material/Batch details display correctly on both classic and block-based Cart/Checkout — see `docs/ARCHITECTURE.md` §9.
- **Phase 8 (Custom Orders & Proof Foundation)** — done: a separate "Create a Custom Label" flow (`wp yeffoprint setup-pages` creates its page) collects size, material, quantity, compound/strength, brand name, style/colors, instructions, and up to 5 validated inspiration files (PDF/SVG/PNG/JPG — SVGs are parsed and sanitized, not just MIME-checked), then charges the $25 design fee through the same cart/checkout as everything else. Payment completion publishes the CustomOrder record and starts its own six-state production pipeline (Design in progress → Proof ready → Awaiting approval → Approved → Printing → Shipped), tracked separately from WooCommerce's order status. Staff can upload Proofs against a request from wp-admin, which auto-advances the status — the customer-facing proof approval UI itself is an explicit V1 non-goal, so this phase only had to not require a rebuild to add it later.
- **Phase 9 (Accounts & Reordering Foundation)** — done: a fully branded My Account dashboard (real template override, not default WooCommerce visuals) with the exact section order PROJECT_SPEC §16 asks for — Orders, Saved Designs, Rewards, Proofs, Addresses. Proofs is real (a customer's own custom design requests and any uploaded proof files); Saved Designs became real in the V2 pass below, Rewards is still a navigation placeholder. Reorder is real too — a "Reorder this design" link per order line item restores that exact batch into the configurator to review and edit before adding to cart again (never a one-click re-cart, which the spec deliberately avoids), reusing the same rehydration path "Edit customization" already used. WooCommerce's native "Order Again" button, which can't work for anything this store sells, is hidden in favor of it.

## V2

V1's explicit non-goals (PROJECT_SPEC §19), built out one at a time now that the foundation they needed exists:

- **Saved Designs** — done: a customer can save a design (template + size + material + the whole variant batch, unfinished fields allowed) from the configurator without buying, see them listed under My Account → Saved Designs, and restore one back into the configurator to finish/edit before ordering. Reuses the exact rehydration shape and pattern "Edit customization"/Reorder already established (`GET .../{id}` → `{template_id, size_id, material_id, variants}` → `hydrateFromBatch()`), so the configurator needed only a new source URL, not new logic. New `yp_saved_design` CPT, customer-owned via native `post_author`.
- One-click Reorder UI, online proof approval UI, a rewards dashboard, and a referral system are still to come.

- **Phase 10 (QA & Optimization)** — done: an audit across responsive/a11y/performance/security/browser-compat/cleanup, fixed in place. Security: closed a CSRF gap on the cart/custom-order write endpoints (nonce-checked for logged-in requests, guests unaffected), SVG upload detection now sniffs content instead of trusting the filename extension, and the upload endpoint is IP-rate-limited. Accessibility: the configurator's Size/Material pickers and Label/Vial tabs now expose their selection state correctly (`radiogroup`/`radio`, linked `tablist`/`tabpanel` with arrow-key navigation), the live price summary announces changes (`aria-live`), a broken form label was fixed, and several color/text combinations (including some from the color-scheme pass above) were swapped for AA-compliant "deep" shades. Performance: typing in a customization field no longer rebuilds the whole preview stage per keystroke. Also fixed: the `/custom-stickers/` nav links 404'd on a fresh install (now a real "coming soon" page), the sticky configurator preview no longer assumes a fixed header height, and the newsletter form now says signups aren't open yet instead of silently doing nothing.

See `docs/PROJECT_SPEC.md` §21 for the full phased delivery plan.
